# Address line — the thread grammar that survives full width

Status: approved for build. Direction: `docs/creative/DIRECTION-thread-visualisation.md`.
Research: `docs/research/thread-visualization-survey.md`. Target: Mammut 1.2.0.

The reply rail is gone in full-width mode because it lived in the avatar gutter and full width puts
text there. This replaces it with something the rail never did: **say who the post is answering, and
say where the fetched view honestly ends.** One grammar, two renderings — the layout may change the
decoration, never the information.

## 1. The rule set

Every status in Conversation gets exactly one of these, decided by data we actually have:

| Case | Visible text | Notes |
|---|---|---|
| Reply to a different author, parent post present in the fetch | `Replying to {display name}` | The normal case. Carries the parent's custom emoji. |
| Reply to a different author, account known, parent post **absent** | `Replying to {display name} · parent post not shown` | Never bridge the gap with a connector. |
| Reply to a different author, account **unresolved** | `Replying to a post that isn't shown` | Never leak an id, never invent a name. |
| Self-reply, chain position known | `Thread {n}/{N}` | `n` is this post's index in the fetched chain, `N` the chain size. |
| Self-reply, chain not eligible / bounds unknown | `Thread` | Bare, quiet, no number. A number is a claim. |
| Not a reply, or top of the conversation | nothing | No empty row, no placeholder. |

`n/N` is a statement about **the posts Mammut fetched**, not about the conversation's true size. The
end line in §3 says so in words; the badge must not imply more.

## 2. Where it renders

It is a text row, bound like any other list row — **not** a decoration, and it must not depend on a
left gutter existing.

- **Indented layout:** the address line sits above the author header, at the row's normal content
  inset (16 dp inside the item, i.e. 64 dp from the edge). The old rail may stay as redundant
  adjacency reinforcement; nothing may be rail-only.
- **Full-width layout:** the same row at 16 dp from the edge, above the author header. Body text,
  media and actions keep their full width. No fake gutter, no second column, no overlay on content.
- **Unroll:** the address line is suppressed inside Unroll (the reading mode has its own numbering
  and the chain is already the subject). It returns when Unroll is switched off.

The row reuses `ReblogOrReplyLineCustomStatusDisplayItem` and `display_item_reblog_or_reply_line_custom.xml`
where possible; if the existing row cannot express the three states, extend it rather than adding a
second look-alike row type.

## 3. The honest end line

When the Conversation list is exhausted, one quiet row at the end:

- `End of the {n} posts Mammut fetched` where `n` is the number of statuses actually fetched for this
  conversation.
- Never `End of conversation`, never `End of thread`, never a count we did not fetch.
- Not shown while more pages can still load, and not shown in Unroll (Reading Room has its own footer).

## 4. Data and computation

Resolve once, when display items are built — never in `onDraw`, never in a scroll callback:

- Parent author name: `status.inReplyToAccountId` → `knownAccounts`; fall back to the parent status
  found in the fetched context; fall back to the unresolved state.
- Self-reply: parent author id equals this status's author id.
- Chain position: `ConversationChain` (already computed for the subtitle and for Unroll). `n/N` only
  when the chain is eligible.
- Long names: truncate the visible name at 24 characters with `…`; the full name goes into the
  accessibility label. Do not truncate the `· parent post not shown` suffix.

Put the decision in a pure class (`ThreadAddressRule`) that takes plain inputs — parent name present
or not, parent account resolved or not, same author or not, chain index and size or absent — and
returns the visible string and the accessibility string. That is what the unit tests drive.

## 5. Accessibility

Every state has a spoken equivalent in normal reading order, emitted as the row's content
description, before the post body:

- `Replying to {name}`
- `Replying to {name}, parent post not shown`
- `Replying to a post that isn't shown`
- `Self-reply, thread {n} of {N}`
- `Self-reply, part of a thread`

Colour and icons may reinforce these states; they may not define them. No announcement may be
generated by scrolling.

## 6. Unroll in full width (the plan conflict)

`docs/READING-ROOM-SPEC.md` §5.2–5.3 pins Unroll's reading line and numbering to a left gutter, and
Unroll rows are full width with a 44 dp left inset — the same geometry problem, unfixed.

In **full-width** Unroll:

- Remove the 44 dp body inset and the drawn reading line.
- Move the existing `n/N` marker into the bound row (a compact header line or the address row) at
  16 dp. Nothing is drawn in `ItemDecoration`.
- Side-branch markers, counts, ordering, the "All N posts" escape and the honest footer stay exactly
  as they are.

In **indented** Unroll nothing changes: the reading line and gutter numbering stay, because the
gutter genuinely exists there.

## 7. Performance

- No `String` formatting, `drawText`, new `Path`/`Rect` or account lookup inside `onDraw`,
  `onDrawOver` or a scroll callback. Precompute labels with the items.
- Full-width structure may occupy a header, a gap, or its own row. It may not add a left `outRect`
  or narrow the text column.

## 8. Tests

JVM tests for `ThreadAddressRule` over the full truth table in §1: cross-author present, cross-author
with absent parent, unresolved parent, self-reply with known bounds, self-reply with unknown bounds,
not-a-reply, and long names (24-character clamp, full name preserved in the accessibility string).

Device checks (orchestrator, since emulators segfault here): one conversation in each layout with a
cross-author reply, a self-thread, a reply whose parent is not in the fetched context, and the end of
the list visible. Both layouts, light and dark.

## 9. Done means

- §1's table is implemented with no case falling through to a blank row or a raw id.
- The end line never claims more than was fetched.
- Full-width mode shows no left inset for any of these rows, and Unroll no longer reserves 44 dp.
- TalkBack reads every state in the wording of §5 (verify by reading the strings, not by running
  TalkBack on a device we cannot attach an accessibility service to).
- No new dependency; no change to the indented layout's existing appearance beyond the added row.
